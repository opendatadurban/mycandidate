Technical documentation

This page summarises the technology behind MyCandidate. It lives in its own /technical directory, separate from the marketing pages, so it can grow independently. For the full, always up-to-date setup guide see the repository README.

Architecture overview

MyCandidate is a server-rendered Flask application. Candidate, election and location data is stored in PostgreSQL and served through Flask routes and Jinja templates (main/routes.py, main/templates/). Configuration for each country or election deployment lives under main/config/, which lets the same codebase be re-used across different elections. Redis is used for caching and background task management. This /site directory is intentionally separate: it is a static, dependency-free site that documents the project and is deployed independently to Netlify, without needing the Python application, a database, or Redis.

Local application setup (quick reference)

git clone https://github.com/opendatadurban/mycandidate.git
cd mycandidate
python -m venv env && env/Scripts/activate   # Windows
pip install -r requirements.txt
cp dexter/config/example.development.cfg dexter/config/development.cfg

# create the PostgreSQL database, then:
python rebuild_db.py

# run the test suite
pytest

Redis is required for caching and background jobs — see the README for install instructions per platform, and set REDIS_URL in your config file.

Deploying this static site

This documentation site has no build step. Netlify is configured (see netlify.toml at the repository root) to publish the /site directory directly:

[build]
  publish = "site"

To preview locally, just open site/index.html in a browser, or serve the folder with any static file server.
